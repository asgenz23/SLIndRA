| Rule | Before | After | Impact |

**Example Change**:

**BEFORE** (Duplicated in quality-control):
```
A missing year has zero usable daily values. A partial year 
below 75% coverage is a failing annual Level 2 year...

Storm years run May 1-April 30 and are labeled by starting year.
Storm-year completeness is computed over the full storm-year 
denominator. A storm year passes if usable-day coverage is at 
least 75%.
```

**AFTER** (Governance):
```
## Temporal Aggregation and Data Completeness Rules

### Storm Year
- **Definition**: May 1 – April 30 (inclusive)
- **Labeling**: Label by starting year (storm year 2020 = May 1, 2020 – April 30, 2021)
- **Completeness Rule**: Storm year passes if usable-day coverage ≥ 75% of expected days

### No-Data Preservation
- **True no-data periods**: Represent as missing/empty/NaN
- **Partial-data periods**: Carry forward with QC diagnostics
- **Rationale**: Preserves interpretability and enables downstream validation

### Reference Documentation
For detailed daily-interval rules... see cindra-quality-control...
```

- ✅ 75% rule stated consistently
- ✅ Storm-year definition unified
- ✅ No-data handling explicit

#### 2C: Downstream Workflow Triggers in Site Setup

**NEW SECTION**: "Downstream Workflow Triggers"

Explicit 4-step sequence after site config:

1. **Quality Control** (optional but recommended)
   - Input: Site config
   - Output: QC summary, Level 2 pass/fail, completeness fractions
   - When: Before trend/flood-freq for primary products

2. **Trend Analysis** (requires site config ± QC)
   - Input: Site config + QC reference (if available)
   - Output: `station_trend_summary.csv`, trend maps, time series

3. **Flood-Frequency Analysis** (parallel to Trend)
   - Input: Site config + QC reference
   - Output: `flood_frequency_summary.csv`, flood-day tables

4. **Product Assembly** (final)
   - Input: All domain outputs + QC diagnostics
   - Output: Inventory, captions, methods, validation checklist
